# LearnPath AI – Current Project Status

**Updated:** November 5, 2026  
**Project:** `D:\AI LEARNING PLATFORM`

## Implemented and verified

- Registration and login use the backend; offline demo sessions and automatic demo login have been removed.
- New accounts begin with zero XP and no pre-completed lessons or study tasks.
- Student roadmaps, topic progress, quiz attempts, planner tasks, and settings are stored through authenticated backend routes.
- Topic completion is sequential and idempotent. Invalid or locked-topic updates are rejected.
- Quizzes present up to five questions one at a time, retain selected answers, require a complete submission, and store results and explanations.
- AI Tutor requests use the configured Gemini models, carry recent chat turns into follow-ups, and return an explicit service error when no live response is available. Generated Markdown is sanitized before rendering.
- Dashboard and progress pages no longer show seeded profile or activity metrics when an API request fails.
- Preference values persist in a new `user_preferences` table. Email and reminder delivery are not configured; the UI says so.
- Planner completion timestamps are added with a non-destructive schema migration. Existing records are retained; old tasks do not receive fabricated timestamps.
- CORS is restricted to local app origins by default. Production can set `FRONTEND_ORIGINS` and must configure a unique `JWT_SECRET`.
- Legacy verification scripts now run the isolated pytest suite instead of editing student records.

## Verification results

- Backend integration suite: **40 passed** in the project folder using isolated databases under the task work folder.
- Frontend production build: **passed** in the project folder (`tsc -b` and Vite production build).
- Student journey integration test covers registration, dashboard, sequential roadmap progress, quiz scoring/history, planner create/complete/delete, settings persistence, and contextual tutor follow-up.
- Gemini fallback tests simulate a primary HTTP 503 and confirm the secondary model is called. A live check then observed `gemini-3-flash-preview` time out and `gemini-3.6-flash` return a response.
- No historical application log was present for the original reported 503, so that exact request's upstream response could not be reconstructed.

## Known limits

- The live check verified one successful fallback; it does not guarantee that Google will never return errors for both models.
- Roadmaps use curated templates and rule-based generation; they are not generated by Gemini.
- The custom-topic quiz generator uses transparent templates; it does not call Gemini.
- Planner time is estimated from planned durations. The application does not run a study timer.
- Notification preferences are saved, but email and reminder delivery are not implemented.
- Existing completed tasks have no historical completion date; they remain in totals but are omitted from dated weekly activity.
- A browser-based manual UI smoke pass was not run. The backend student journey and frontend production build were verified separately.

## Run locally

Backend, from PowerShell:

```powershell
Set-Location 'D:\AI LEARNING PLATFORM\backend'
python run.py
```

Frontend, in a second PowerShell window:

```powershell
Set-Location 'D:\AI LEARNING PLATFORM'
npm run dev
```

Run isolated backend tests from the project root:

```powershell
Set-Location 'D:\AI LEARNING PLATFORM'
python -m pytest
```

Build the frontend:

```powershell
npm run build
```

Keep `GEMINI_API_KEY` in `backend/.env`; never put it in frontend code.
